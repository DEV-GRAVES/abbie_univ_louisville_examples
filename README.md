# abbie_univ_louisville_examples

Example repository for Abbie Beauerle @ abigail.beauerle@louisville.edu containing a project scaffold with python code and a working output. Used for observing modern practices for how solution and software design teams create transparency and communicate through code.

It shows four common deliverables on a small, realistic supply-chain analytics project:

| # | Example | Location |
|---|---|---|
| 1 | Technical documentation | [`docs/TECHNICAL_DOCUMENTATION.md`](docs/TECHNICAL_DOCUMENTATION.md) |
| 2 | Python code with heavy comments and version/change references | [`src/fill_rate_analyzer.py`](src/fill_rate_analyzer.py) |
| 3 | Interactive HTML report generated by that code | [`reports/fill_rate_report.html`](reports/fill_rate_report.html) |
| 4 | Change log and team communication shown inside the report | [`CHANGELOG.md`](CHANGELOG.md), [`docs/team_communication.json`](docs/team_communication.json) |

## The scenario

Three warehouses (Louisville, Memphis, Indianapolis) ship customer orders. The team wants to know **fill rate** (did we ship everything ordered?) and **on-time rate** (did we ship by the promise date?), broken down by site, product family and day.

## Quick start

Requires Python 3.9+. No packages to install.

```bash
git clone https://github.com/<your-account>/abbie_univ_louisville_examples.git
cd abbie_univ_louisville_examples
python src/fill_rate_analyzer.py --generate-sample
# open reports/fill_rate_report.html in a browser
python -m unittest discover tests
```

## Things worth studying

- **Inline change tags** like `# [v1.1.1] [CHG-091]` in the Python file link each line to a release and a ticket.
- **The bug-fix comment pattern**: the old line is kept as an `OLD:` comment beside the fix.
- **Single source of truth**: `__version__` drives the report footer, and the report's change log is read from `CHANGELOG.md`; a test fails if they disagree.
- **Git tag** `v2.1.0` matches `__version__` and the top entry in `CHANGELOG.md`.
